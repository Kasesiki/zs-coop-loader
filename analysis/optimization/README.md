# 第一轮优化实验

这里存放候选脚本和验证记录，不是游戏当前正在使用的补丁。除非经过
运行时计数、帧时间和行为回归验证，否则不把候选代码写回原始 `data.win`。

## 当前判断

### 子弹碰撞

`bullet_check_for_collisions` 的三次 `collision_line_list` 是明确的热点，但
目前不能安全地删除其中任何一次：子弹可能同时经过墙体、NPC 和玩家，代码
需要保持最近命中顺序。下一步应先测量三类列表的平均长度和空查询比例，再
设计空间分桶或合并查询。

### 视线检测

`instance_line_of_sight` 是最适合做第一个行为保持型实验的入口。候选实现只
缓存同一房间、同一观察者坐标、同一目标坐标的最近结果，最多保留两帧。坐标
变化或房间变化会立即失效。该候选仍可能因动态障碍物造成短暂陈旧结果，因此
默认不启用。

## 验证矩阵

```text
场景                    观测指标                         通过条件
普通单发                子弹碰撞调用/帧、帧时间          命中行为不变
霰弹枪                  子弹实例数、列表查询数           无重复命中、无穿墙
穿透目标                命中顺序、命中点、穿透次数       与基线一致
NPC 密集战斗            LOS 调用数、AI 帧时间             无明显目标延迟
房间切换                缓存命中率、缓存失效次数          不读取旧房间结果
动态障碍物              LOS 结果与基线对比                不产生穿墙判断
```

## 应用顺序

1. 先做只读计数和基线录制。
2. 只在分析副本上编译候选代码。
3. 使用独立输出 `data.win` 启动测试。
4. 通过碰撞、AI、房间切换和存档回归后，再接入加载器。
